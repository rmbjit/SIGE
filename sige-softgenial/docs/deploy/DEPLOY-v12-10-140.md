# SIGE SoftGenial v12.10.140 - Security Baseline PRO

## Antes de instalar
Base: v12.10.139 validada.
Escopo: segurança transversal.

## Pontos que podem exigir ajuste operacional

### 1. Cron central WhatsApp
A chave fixa antiga deixou de ser aceite. Cada instalação passa a gerar uma chave própria:

- option: `sige_wpp_queue_cron_key`

O cron central deve preferir header:

- `X-SIGE-Cron-Key: <chave>`

Também continua a aceitar `?key=<chave>` por compatibilidade, mas o header é mais seguro.

### 2. Webhook WhatsApp
O endpoint público passa a exigir HMAC ou segredo:

- option: `sige_sec_secret_whatsapp_webhook`
- header simples: `X-SIGE-Webhook-Secret: <segredo>`
- alternativa transitória: `?sige_webhook_key=<segredo>`

Para HMAC:

- `X-SIGE-Timestamp: <unix_timestamp>`
- `X-SIGE-Signature: HMAC_SHA256(timestamp + '.' + raw_body, segredo)`

### 3. Hub instant refresh
O endpoint `/wp-json/sige/v1/hub/instant-refresh` passa a exigir HMAC ou segredo:

- option: `sige_sec_secret_hub_instant_refresh`

O Hub central deve assinar chamadas ou enviar o segredo no header seguro.

### 4. Updates automáticos
A v12.10.140 bloqueia pacote de update fora de host autorizado e, por padrão, exige checksum SHA-256 no manifesto.

Campos aceites no manifesto:

- `sha256`
- `checksum_sha256`
- `checksum`

Se o manifesto antigo ainda não tiver checksum, o update automático pode ser bloqueado por segurança. A instalação manual via ZIP continua possível.

### 5. Reset de senha
O sistema deixa de enviar ou mostrar senha em texto claro. O reset passa a enviar link único de definição de senha.

## Validação local feita

- `php -l` em todos os ficheiros PHP: OK.
- `unzip -t` no ZIP final: OK.
