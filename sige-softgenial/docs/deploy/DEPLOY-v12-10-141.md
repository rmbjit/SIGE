# SIGE SoftGenial v12.10.141 - Security Baseline PRO: Webhook Off & REST Hardening

## Antes de instalar
Esta versão assume que a escola/SoftGenial já não usa webhook WhatsApp/Z-API inbound.

## O que muda
1. `/wp-json/sige/v1/whatsapp-webhook` fica desligado por defeito.
2. Se alguém tentar aceder ao endpoint, recebe 404.
3. O processamento da fila WhatsApp deve usar header seguro:

```bash
curl -X POST "https://ESCOLA/wp-json/sige/v1/process-queue" \
  -H "X-SIGE-Cron-Key: SUA_CHAVE_CRON_DA_ESCOLA"
```

Ou:

```bash
curl -X POST "https://ESCOLA/wp-json/sige/v1/process-queue" \
  -H "Authorization: Bearer SUA_CHAVE_CRON_DA_ESCOLA"
```

## Compatibilidade temporária
Se ainda existir algum cron antigo a chamar `?key=...`, ele pode deixar de autenticar. O caminho recomendado é actualizar o cron central para enviar a chave no header.

Compatibilidade por URL só deve ser usada temporariamente:

```php
define('SIGE_ALLOW_CRON_KEY_IN_QUERY', true);
```

## Reactivar webhook, se um dia for necessário
Não recomendado se não estiver em uso. Para reactivar:

```php
define('SIGE_WPP_WEBHOOK_ENABLED', true);
```

Mesmo reactivado, o webhook continua a exigir segredo/HMAC.

## Validação pós-instalação
- Entrar no sistema normalmente.
- Confirmar que os módulos financeiros/académicos abrem.
- Testar um pagamento sem enviar WhatsApp imediato.
- Confirmar que a fila processa via cron com header.
- Aceder a `/wp-json/sige/v1/whatsapp-webhook` e confirmar 404 se webhook estiver desactivado.
