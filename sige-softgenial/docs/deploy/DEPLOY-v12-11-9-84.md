# DEPLOY v12.11.9.84 - Histórico Financeiro Hotfix Multi-Tenant

**Pacote:** `sige-softgenial-v12_11_9_84-historico-financeiro-hotfix-multitenant.zip`
**Tipo:** pacote completo do plugin (instalação integral, nunca por blocos).
**Base validada:** v12.11.9.83.
**Objectivo:** eliminar o erro "Unknown column 'm.status' in 'SELECT'" no documento de extracto/histórico financeiro em escolas cuja tabela de matrículas não tem a coluna `status`.

## Instalação (Hostinger File Manager, sem SSH)
1. Faça cópia de `wp-content/plugins/sige-softgenial/` antes de substituir.
2. No File Manager, vá a `wp-content/plugins/`.
3. Renomeie a pasta actual para `sige-softgenial_bkp_v83/`.
4. Carregue o ZIP `sige-softgenial-v12_11_9_84-...zip` para `wp-content/plugins/` e extraia. Deve ficar `wp-content/plugins/sige-softgenial/`.
5. Confirme no Painel de cada escola que a versão activa é **12.11.9.84**.
6. Limpe caches (LiteSpeed/Cloudflare e cache de página).

> O SigeHub no site-mãe continua a controlar licenças/cobrança. Não é preciso reactivar licenças.

## Verificação rápida pós-instalação (no caso Malisa)
1. Abra o histórico financeiro/extracto do aluno que dava erro (ex.: processo 00248).
2. O topo do documento **já não deve mostrar** o aviso "Erro da base de dados do WordPress: [Unknown column 'm.status'...]".
3. Se o aluno tiver matrícula com turma no ano lectivo, a "Turma actual" passa a aparecer; se não tiver, continua a indicar "Sem turma" (sem erro).
4. Confirme que valores financeiros (dívida, entradas, pagamentos) continuam exactamente como antes.

## Notas de segurança/integridade
- Nenhuma regra financeira ou académica aprovada foi alterada.
- Sem alterações de base de dados (sem CREATE/ALTER/DROP TABLE). A correcção apenas **lê** a estrutura para se adaptar.
- A consulta passou a usar `status_matricula`, depois `status`, e por fim um valor vazio.

## Rollback
Restaure `sige-softgenial_bkp_v83/` para `sige-softgenial/` e limpe caches. (O erro de `m.status` voltaria a aparecer nas escolas sem essa coluna.)
