# SIGE SoftGenial v12.10.142 - Security Baseline PRO: Update Origin Hotfix

## Problema corrigido
A v12.10.141 podia bloquear indevidamente a instalação/actualização manual com a mensagem:

> Actualização bloqueada: origem do pacote não autorizada.

Isto acontecia porque a validação de origem do pacote era demasiado agressiva e podia tratar um ZIP carregado manualmente como se fosse pacote remoto.

## Como instalar esta versão
Preferencialmente, faça upload deste ZIP pelo painel WordPress.

Se a versão instalada ainda bloquear por causa do filtro antigo da v12.10.141, use uma destas alternativas seguras:

1. Renomear o ZIP antes do upload para um nome sem `sige-softgenial`, por exemplo:
   `sg-12-10-142.zip`

2. Ou desactivar temporariamente o plugin antigo, instalar o ZIP novo e reactivar.

3. Depois de a v12.10.142 estar instalada, existe também um bypass técnico de emergência para futuras recuperações:

```php
define('SIGE_DISABLE_UPDATE_ORIGIN_GUARD', true);
```

Use apenas temporariamente e remova depois da recuperação. Nota: este bypass não existe na v12.10.141, por isso, para sair da v12.10.141, as opções mais seguras são renomear o ZIP ou desactivar temporariamente o plugin antigo antes do upload.

## O que se mantém protegido
- Updates remotos oficiais continuam sujeitos a host autorizado.
- Manifesto remoto continua a poder exigir checksum SHA-256.
- Upload local/manual deixa de ser bloqueado porque não representa download remoto por URL.

## Configurar hosts autorizados adicionais
Se o Hub distribuir pacotes por outro domínio controlado pela SoftGenial, pode configurar:

```php
define('SIGE_ALLOWED_UPDATE_HOSTS', 'softgenial.edu.mz,www.softgenial.edu.mz,updates.softgenial.edu.mz');
```

Também pode usar o filtro `sige_allowed_update_hosts` ou a opção `sige_allowed_update_hosts`.

## Validação pós-instalação
- Confirmar que o plugin mostra versão 12.10.142.
- Confirmar que o Dashboard abre.
- Confirmar que Pagamentos, Matriz Curricular e Alunos abrem normalmente.
- Confirmar que o cron WhatsApp continua a processar via header seguro.
- Confirmar que updates remotos passam apenas quando o host e o checksum são válidos.
