# RC6 v12.16.0 - Professor Route Hotfix

## Situacao

Durante validacao humana em staging, o perfil Professor entrou em processamento continuo ao abrir a area Minhas Turmas. A URL observada foi:

`admin.php?page=sige-app#038;view=minhas_turmas`

Esta URL nao entrega `view=minhas_turmas` ao servidor. O trecho `#038;view=minhas_turmas` vira fragmento do browser e a view perde-se antes de chegar ao PHP.

## Classificacao

- Prioridade: P1 bloqueador de RC
- Area afectada: acesso docente e fallback de redireccao do dashboard
- Area nao afectada: financeiro, formulas, recibos, notas, pautas, schema e permissoes reais
- ZIP final: bloqueado ate nova validacao em staging

## Causa raiz

O redirect de fallback em `admin/system/dashboard-view.php` usava `esc_url()` dentro de uma string JavaScript:

`window.location.href="..."`

Em contexto `<script>`, `esc_url()` pode emitir `&#038;` para representar `&`. Como o conteudo de `<script>` nao e tratado como atributo HTML normal, o browser interpreta `#038` como fragmento da URL. O parametro `view` deixa de existir na query string.

## Correcao aplicada

Substitui a interpolacao com `esc_url()` por serializacao segura com `wp_json_encode()` e `window.location.replace()`.

Rotas protegidas:

- Professor: `admin.php?page=sige-app&view=minhas_turmas`
- Educador: `admin.php?page=sige-app&view=jardim_diario`

## Risco reduzido

- Evita loop de processamento quando o perfil Professor e redireccionado para Minhas Turmas.
- Evita perda de `view=` em redireccoes JavaScript.
- Mantem a matriz de permissoes como fonte de verdade.
- Nao alarga acesso a nenhuma area.

## Rollback

Rollback localizado:

1. Repor o bloco anterior de redirect em `admin/system/dashboard-view.php`.
2. Remover os dois gates RC6 de `tools/run-gates.php`.
3. Remover os docs RC6.

Nao ha migracao de dados nem alteracao de schema.
