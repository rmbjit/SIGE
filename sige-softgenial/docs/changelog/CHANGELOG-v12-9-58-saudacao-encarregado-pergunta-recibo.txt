CHANGELOG v12.9.58 - Saudação por Encarregado + Pergunta sobre link do recibo
==============================================================================
Data: 2026-05-04
Base: v12.9.57 notification-policy

OBJECTIVO
---------
Refinamento das mensagens de confirmação de pagamento conforme feedback dos
clientes (Maio 2026):

1. A saudação volta a ser pelo nome do ENCARREGADO (não do aluno como na v12.9.57).
2. Quando o nome do encarregado está vazio no formulário do aluno, usar o
   fallback fixo "Encarregado de Educação".
3. Mensagem deve TER SEMPRE uma pergunta a convidar o encarregado a pedir o
   link do recibo digital - em vez de enviarmos o link automaticamente.

ALTERAÇÕES
----------

includes/whatsapp-templates-conversacional.php
  - Bloco de variáveis comuns do recibo refactorado: cascata de fontes do
    nome do encarregado.
  - Cascata: $vars['encarregado'] (do dual-send) → aluno.nome_pai →
    aluno.nome_mae → aluno.contacto_encarregado → fallback "Encarregado de
    Educação".
  - Marcador "Encarregado(a)" vindo de notificacoes-encarregados.php quando
    o nome real está vazio → tratado como vazio e cai no fallback.
  - Pergunta SEMPRE incluída no fim do recibo:
        "📄 Posso partilhar o link do recibo digital por aqui - quer receber?"
  - A pergunta termina com "?" propositadamente - assim a regex
    /\?\s*$/u em sige_wpp_humanize_message() (recovery-mode) reconhece e
    NÃO anexa outra pergunta. Anti-duplicação garantida.

admin/finance/financeiro-pagamentos.php
  - Removida passagem de 'link' => $link_recibo_publico nas DUAS chamadas
    (dual-send principal + fallback legacy).
  - Razão: se passássemos o link, o engine anexaria-o e o
    sige_wpp_prepare_queue_messages removeria + adicionaria pergunta
    automática (duplicação com a nossa pergunta no template).
  - Sem link nas vars, o template trata da mensagem completa de forma
    auto-contida, com a nossa pergunta única no fim.

includes/notificacoes-encarregados.php
  - Revertido o hook sige_notify_normalize_saudacao_aluno.
  - Razão: a v12.9.57 substituía "Encarregado(a)" por nome do aluno. Com a
    nova regra (saudação por encarregado), essa substituição deixou de fazer
    sentido. O fallback "Encarregado de Educação" é tratado directamente no
    template.

TRADE-OFF CONHECIDO
-------------------
O fluxo "envio do link sob pedido" do recovery-mode (que enviaria o link
automaticamente quando o pai responde "sim") deixa de disparar - porque
sem 'link' nas vars, o sige_wpp_store_pending_receipt() não é chamado.

Para esta release, quando o encarregado responder, a secretaria precisa
enviar o link manualmente. Em iteração futura, podemos religar este pipe
para enviar automaticamente o link após resposta positiva.
