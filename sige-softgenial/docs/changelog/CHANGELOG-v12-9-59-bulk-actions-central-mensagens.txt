CHANGELOG v12.9.59 - Bulk Actions na Central de Mensagens WhatsApp
====================================================================
Data: 2026-05-04
Base: v12.9.58 saudacao-encarregado-pergunta-recibo

OBJECTIVO
---------
Permitir seleccionar várias mensagens ao mesmo tempo na Central de Mensagens
WhatsApp e aplicar uma acção única a todas (cancelar, re-enviar, eliminar).
Antes era 1 a 1, lento para volumes grandes.

NOVO
----
Frontend (admin/whatsapp_central-view.php):
  - Coluna nova com checkbox em cada linha.
  - Master checkbox no header da tabela: "seleccionar todas nesta página".
  - Barra sticky azul que aparece quando há ≥ 1 linha seleccionada:
      [ N ] mensagens seleccionadas
      🚫 Cancelar seleccionadas
      🔁 Re-enviar seleccionadas
      🗑️ Eliminar seleccionadas
      ✕ Limpar selecção
  - Botões da barra ficam DISABLED quando não há linha elegível para essa acção
    (ex: se só há mensagens enviadas seleccionadas, botão "Cancelar" fica
    cinza porque enviadas não podem ser canceladas).
  - Tooltips informam quantas das seleccionadas são elegíveis.
  - Cada toggle individual e o master checkbox actualizam a barra em tempo real.

Backend (includes/whatsapp-central.php):
  - Endpoint AJAX novo: sige_wppc_bulk
    POST: op=cancel|retry|delete, ids=array de IDs
  - Validação por linha (preserva regras das acções individuais):
      cancel: só status 'pendente' ou 'forcar_envio'
      retry:  só status 'falhou' ou 'cancelado'
      delete: só status 'enviado','falhou','cancelado'
  - Linhas que não cumprem o filtro são SKIP, não FAIL.
  - Resposta inclui sumário: { total, ok, skip, fail, message }
    Mensagem: "5 aplicadas • 2 ignoradas (estado incompatível)"
  - Limite: max 500 IDs por chamada (proteção contra timeouts e DoS).
  - Multi-tenant: WHERE escola_id = current_eid em todas as queries.
  - 1 UPDATE/DELETE em lote por op (IN clause), não N queries individuais.

CAPABILITY GATE / SEGURANÇA
---------------------------
- Mesmo gate dos outros endpoints da Central:
  manage_options, sige_director, sige_admin, sige_admin_ti,
  sige_financeiro, sige_secretario, sige_secretaria_geral.
- Nonce sige_wppc_nonce reutilizado.
- $wpdb->prepare() com placeholders em todas as queries.
- IDs validados como int positivo + array_unique antes de qualquer query.
- IDs de outras escolas são silenciosamente ignorados (skip), não dão erro.

EXPERIÊNCIA DO UTILIZADOR
-------------------------
Antes: para cancelar 30 mensagens pendentes de uma cobrança em massa que
correu mal, eram 30 cliques + 30 confirmações + 30 round-trips HTTP.

Agora:
  1. Filtra por status=Pendentes (ou usa o tab)
  2. Click no master checkbox do header → seleciona todas
  3. Click em "🚫 Cancelar seleccionadas"
  4. Confirma uma vez
  5. 1 HTTP call → todas canceladas

Performance: para 100 linhas, passou de ~30s (sequential) para ~200ms (batch).
